# 网站安全监测系统 (Web Security Monitor)

## 一、项目背景与需求

### 场景
重保期间（国庆、春节等，一般 10-15 天）对政府客户网站进行远程安全监测，检测页面是否被篡改或挂马。

### 约束条件
1. **不在服务器安装软件** — 和普通用户一样，只能远程通过 HTTP 检测
2. **客户有 WAF** — 需要规避 WAF 拦截，避免被误判为攻击扫描
3. **客户多是政府单位** — 网站为信息系统登录页、门户首页、环境监测展示页等
4. **多客户管理** — 每个客户独立建基线、独立报告、独立告警
5. **不登录检测** — 只检测公开可访问页面，不处理需要登录的内部页面

### 检测方式
分层检测策略：
- **DOM 比对**（主）：对比基线 HTML 和当前 HTML 的结构差异（脚本/iframe/标题/文本/body）
- **截图像素对比**（辅）：前后截图做像素 diff，差异区域红色标注，>5% 变化告警
- **关键词扫描**（宁杀错不放过）：扫描原始 HTML（含标签属性），命中敏感关键词立即告警

### 判定等级
- **挂马 (malware)**：外部域名脚本注入、内联脚本变更、新增 iframe、敏感关键词命中 → 最高优先级
- **篡改 (tamper)**：标题变更、文本变化、body 结构变化、截图差异 → 次优先级
- **不可访问 (unreachable)**：HTTP 非 200、连续 3 次失败 → 触发前重试
- **正常 (normal)**：以上均不触发

### 关键表说明

| 表 | 用途 |
|---|---|
| `baselines` | 建立基线时保存：截图路径、HTML 路径、DOM 指纹 JSON |
| `detection_results` | 每次检测产生一条，`is_retry=0` 为最终结果，`is_retry=1` 为重试中间记录 |
| `detection_logs` | 高频写入的轻量日志，每次请求都记一条 |
| `baseline_history` | 记录每次基线变更（create/update），报告里会引用 |

## 四、关键设计取舍

### 4.1 检测策略

| 决策 | 理由 |
|---|---|
| DOM 对比为主、截图为辅 | DOM 能精准定位脚本/iframe 注入，截图补偿视觉篡改（CSS 被改导致全白等） |
| body_hash 作为兜底规则 | 任何 body 内容变更都逃不掉，其他规则是对变更的细分归类 |
| 文本 5% 阈值不导致漏报 | 文本变化时 body_hash 同时变化并触发告警，5% 阈值只影响 text_changed 自身严重级别 |
| 关键词扫描原始 HTML | 用户选择"宁杀错不放过"，包含标签属性/脚本源码中的敏感词也视为命中 |

### 4.2 WAF 规避

| 策略 | 实现 |
|---|---|
| 串行检测 | 所有 URL 排成队列，顺序执行，不并发 |
| 慢速请求 | 不同域名间默认间隔 8 秒，同域名间 20 秒（可配置） |
| UA 轮换 | 每次请求从预设池中随机取一个 User-Agent |
| 暂停机制 | 同一站点所有页面同时返回 403 → 自动标记 WAF 封禁 → 暂停该站点检测 |
| 手动恢复 | 管理员在站点页面点击"解除封禁"恢复检测 |

### 4.3 重试与阈值

| 参数 | 默认值 | 说明 |
|---|---|---|
| 重试次数 | 3 次 | 失败后重试，超时/连接失败/HTTP 错误都触发 |
| 重试间隔 | 2 分钟 | 每次重试之间等待 |
| 截图差异阈值 | 5% | 像素变化超过此值触发工具告警 |
| 请求超时 | 15 秒 | 政府网站可能有 CDN/防火墙，响应慢 |

### 4.4 基线管理

- **建立时机**：重保开始前 1-2 天手动跑全量建基线
- **更新机制**：检测到变化后，管理员在差异视图审核确认安全，点"确认安全，更新基线"避免反复报警
- **基线内容**：截图（Selenium Edge 全页）+ 原始 HTML + DOM 指纹 JSON
- **变更记录**：每次创建或更新基线写入 `baseline_history`，报告里可追溯
- **数据清空**：删除 `data/` 目录后重启即全量重置

### 4.5 截图全页实现

Selenium 窗口初始 1920x1080，截图前通过 JavaScript 获取页面实际 `scrollWidth/scrollHeight`，`set_window_size` 拉大到全页尺寸后再 `save_screenshot`，保证长页面完整截取。

### 4.6 敏感关键词

- **内置 19 个**：hacked, hacker, defaced, pwned, 赌博, 博彩, 赌场, 六合彩, 时时彩, 色情, 成人, 裸聊, 约炮, 黑页, 黑客, 被黑, backdoor, webshell, shell（不可删除）
- **自定义**：可在设置页手动添加/删除，支持 TXT 批量导入导出（一行一个关键词）
- **扫描范围**：原始 HTML（含标签属性），宁杀错不放过

## 五、技术栈

| 组件 | 技术 | 说明 |
|---|---|---|
| Web 框架 | Flask + Jinja2 | 单用户本地应用，模板渲染，无前后端分离 |
| 数据库 | SQLite | 零配置单文件，`data/monitor.db` |
| HTTP 请求 | requests | UA 轮换，SSL 证书不验证 |
| HTML 解析 | BeautifulSoup4 + lxml | DOM 指纹提取 + 结构对比 |
| 浏览器引擎 | Selenium + Edge | 调用系统自带 Edge 浏览器，webdriver-manager 自动匹配驱动版本 |
| 图像处理 | Pillow | 截图像素 diff + 红色标注 |
| 调度 | threading | 后台线程持续处理检测队列 |
| 时间处理 | SQLite datetime('now','localtime') | 全部使用本地时间（东八区）|

## 七、快速上手

1. **启动**：`pip install -r requirements.txt` → `python app.py` → 浏览器打开 `http://127.0.0.1:5000`
2. **添加监控**：客户 → 站点 → 页面 URL
3. **建基线**：每个页面点"建立基线"
4. **开始检测**：导航栏点"启动"
5. **查看告警**：有异常去"告警管理"→"查看差异"，审核后更新基线
6. **生成报告**：报告页点"生成日报"
7. **交给别人用**：删掉 `data/` 目录后打包源码即可
